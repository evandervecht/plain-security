// BRIEFING

A sandbox for AI. Where should an agent be allowed to run? Een zandbak voor AI. Waar mag een agent draaien?

AI agents now write code, run commands and browse on our behalf. Sooner or later one will follow an instruction we did not give. A good sandbox makes sure that, when it does, it finds nothing of value and has nowhere to send it. Four ways a sandbox falls short, and what a good one looks like. AI-agents schrijven nu code, voeren opdrachten uit en surfen namens ons. Vroeg of laat volgt er één een opdracht die wij niet gaven. Een goede zandbak zorgt ervoor dat hij dan niets van waarde vindt en het nergens heen kan sturen. Vier manieren waarop een zandbak tekortschiet, en hoe een goede eruitziet.

Coding agents and AI assistants that run commands usually start on an employee's laptop or a shared server. There they work with that person's rights: files, saved passwords, cloud keys, and often a route into production. They also read text nobody checked: web pages, tickets, other people's code. A hidden instruction in that text can steer them (see AI at work). NCSC UK (blog, December 2025) warns that this may never be fully fixed inside the model. It advises safeguards outside the model that limit what the system can do. A sandbox is such a safeguard.

Business impact: whatever the person can reach, a hijacked agent can reach too, at machine speed. Built-in sandboxes are not always on: Anthropic's documentation (2026) says the Claude Code sandbox is off by default. We suggest checking the setting rather than assuming it, and giving agents a machine of their own rather than someone's laptop.

Codeeragents en AI-assistenten die opdrachten uitvoeren, starten meestal op de laptop van een medewerker of op een gedeelde server. Daar werken ze met de rechten van die persoon: bestanden, opgeslagen wachtwoorden, cloudsleutels, en vaak een weg naar productie. Ze lezen ook tekst die niemand controleerde: webpagina's, tickets, code van anderen. Een verborgen opdracht in die tekst kan ze sturen (zie AI op de werkvloer). Het NCSC UK (blog, december 2025) waarschuwt dat dit binnen het model misschien nooit helemaal te verhelpen is. Het adviseert waarborgen buiten het model die beperken wat het systeem kan doen. Een zandbak is zo'n waarborg.

Bedrijfsimpact: waar de persoon bij kan, kan een gekaapte agent ook bij, op machinesnelheid. Ingebouwde zandbakken staan niet altijd aan: volgens de documentatie van Anthropic (2026) staat de zandbak van Claude Code standaard uit. Wij raden aan de instelling te controleren in plaats van aan te nemen, en agents een eigen machine te geven in plaats van iemands laptop.

Not every sandbox is equally strong. A container keeps programs apart, but every container on a machine talks to the same kernel. The gVisor documentation (2026) puts it plainly: such a workload is "one system call away from host compromise". Stronger walls exist. gVisor adds its own kernel layer between the program and the machine. A microVM such as Firecracker, which runs AWS Lambda, or a full virtual machine gives the agent a kernel of its own. Anthropic's documentation (2026) calls a dedicated virtual machine the strongest separation.

Business impact: a container is often enough for your own reviewed code. For code an AI wrote after reading the internet, or a repository you do not trust, a stronger wall is worth the extra cost. OWASP lists unexpected code execution among the ten main risks for AI agents (Top 10 for Agentic Applications, December 2025).

Niet elke zandbak is even sterk. Een container houdt programma's uit elkaar, maar elke container op een machine praat met dezelfde kernel. De documentatie van gVisor (2026) zegt het zonder omwegen: zo'n workload is "één systeemaanroep verwijderd van overname van de host". Er bestaan sterkere muren. gVisor zet een eigen kernellaag tussen het programma en de machine. Een microVM zoals Firecracker, waarop AWS Lambda draait, of een volledige virtuele machine geeft de agent een eigen kernel. De documentatie van Anthropic (2026) noemt een eigen virtuele machine de sterkste scheiding.

Bedrijfsimpact: voor uw eigen, beoordeelde code is een container vaak genoeg. Voor code die een AI schreef na het lezen van internet, of een repository die u niet vertrouwt, is een sterkere muur de extra kosten waard. OWASP noemt onverwachte code-uitvoering bij de tien belangrijkste risico's voor AI-agents (Top 10 for Agentic Applications, december 2025).

A sandbox with open internet access and real keys inside is a locked room with the window open. A hijacked agent can send what it reads to any site, or use a key it finds to log in elsewhere. Anthropic's documentation (2026) is plain about it: any sandbox that allows outbound traffic can still leak data the agent can read. Two settings close most of this. Outbound traffic is blocked by default, with a short list of allowed sites. And the real keys stay outside: a broker hands in a short-lived token for one task.

Business impact: without these two, a sandbox protects the laptop but not your data or your cloud account. With them, a hijacked agent finds nothing worth stealing and nowhere to send it. OWASP's AI Agent Security Cheat Sheet advises against unrestricted tool access and wildcard permissions for the same reason.

Een zandbak met open internettoegang en echte sleutels erin is een afgesloten kamer met het raam open. Een gekaapte agent kan wat hij leest naar elke site sturen, of een sleutel die hij vindt gebruiken om elders in te loggen. De documentatie van Anthropic (2026) zegt het duidelijk: elke zandbak die uitgaand verkeer toestaat, kan nog steeds data lekken die de agent kan lezen. Twee instellingen sluiten het meeste hiervan af. Uitgaand verkeer staat standaard dicht, met een korte lijst toegestane sites. En de echte sleutels blijven buiten: een sleutelbeheerder geeft een kortlevend token voor één taak.

Bedrijfsimpact: zonder deze twee beschermt een zandbak de laptop, maar niet uw data of uw cloudaccount. Met deze twee vindt een gekaapte agent niets wat het stelen waard is, en kan hij het nergens heen sturen. De AI Agent Security Cheat Sheet van OWASP raadt om dezelfde reden onbeperkte tooltoegang en jokerrechten af.

"Sandbox" also means a place to try AI. A team starts a pilot in a separate environment. To make the demo convincing, someone copies in real customer data. To make it useful, someone connects a live system. Months later the pilot is in daily use, with no owner, no logging and no review. Personal data in a pilot is still personal data: the GDPR applies there too.

Business impact: the riskiest AI system is often the one nobody decided to run. We suggest three rules for every AI pilot: fake or masked data, an end date with exit criteria, and one route to production through the normal review. Not to be confused with the AI Act's "regulatory sandbox": a supervised test space that the AI Act requires each Member State to have running by 2 August 2027 (Art. 57, date moved by the 2026 AI Omnibus). Worth knowing if you build AI products; it is not a technical control.

"Zandbak" betekent ook een plek om AI uit te proberen. Een team start een pilot in een aparte omgeving. Om de demo overtuigend te maken, kopieert iemand echte klantdata erin. Om hem nuttig te maken, koppelt iemand een live systeem. Maanden later is de pilot dagelijks in gebruik, zonder eigenaar, zonder logging en zonder review. Persoonsgegevens in een pilot blijven persoonsgegevens: de AVG geldt daar ook.

Bedrijfsimpact: het riskantste AI-systeem is vaak het systeem waarvan niemand besloot het te laten draaien. Wij stellen drie regels voor elke AI-pilot voor: nep- of gemaskeerde data, een einddatum met exitcriteria, en één route naar productie via de gewone review. Niet te verwarren met de "regulatory sandbox" uit de AI-verordening: een testomgeving onder toezicht die volgens de AI-verordening elke lidstaat uiterlijk 2 augustus 2027 moet hebben (art. 57, datum verschoven door de AI-omnibus van 2026). Goed om te weten als u AI-producten bouwt; het is geen technische maatregel.

The board-level point: the question is not whether to use AI agents, but where they are allowed to run. We suggest three follow-ups. Where do our AI agents run today, and with whose rights?
