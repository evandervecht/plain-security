# Your website is a front door

## intro {hold=1}
When did someone last try to break our website on our behalf? [#four] It is a front door that anyone on earth can knock on. Four ways in.

## inject
First, a search box that talks to the database. [#form] Every form takes text from a stranger. [#type] If the code does not keep what the visitor typed apart from commands, the visitor can type instructions. [#all] The whole customer database can leave in one request. The GDPR requires notifying the regulator within 72 hours.

## plugin
Second, the plugin everyone forgot. [#many] A website is a content system, plugins, a theme and libraries, each written by someone else. [#pub] When a hole is found, the fix and the description of the hole are published together. [#scan] Scanners then sweep the internet for sites on the old version, and find them in hours.

## stuffing
Third, customer accounts opened with someone else's leak. [#reuse] People reuse passwords. [#bots] A bot network tries leaked pairs against our login page, millions of attempts a night. [#fraud] The result is fraud on our site, refunds we pay, and a headline about us.

## skim
Fourth, our page, their code. [#third] Checkout and login pages load scripts from other companies. [#read] Those scripts can read every field on the page. [#swap] If one supplier is compromised, the script is swapped, payments still succeed, and card numbers go elsewhere.

## good {hold=1.2}
What good looks like. [#pci] The payment card standard, version 4.0.1, requirements 6.4.3 and 11.6.1, requires an inventory of scripts on payment pages, and tamper detection. [#code] Safe code, and a yearly pentest. [#patch] Patches land within days. [#pass] Customers log in with a second factor.

## first {hold=1.2}
A suggested first step. [#ask] Ask when someone last tried to break the site on our behalf. [#paged] And who is paged, by name, when it breaks for real.

## outro {hold=2}
The website is the one system every attacker can reach. [#keep] Test it on purpose.
