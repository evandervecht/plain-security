# Decrease the blast radius: the difference between an incident and a crisis

## intro {hold=1}
When one system is breached, how far does it spread? [#much] The question is not whether we get compromised. It is how much.

## flat
First, one compromised system reaches everything. [#flat] On a flat network, the attacker spreads undetected. [#wall] With segmentation, one hacked system stays an isolated problem. Consider network segmentation and a zero trust architecture.

## password
Second, one password becomes total access. [#shared] Shared admin credentials ignore every privilege boundary. [#domain] In minutes the attacker holds domain admin, and everything is readable. [#tier] Consider tiered admin accounts, separate devices and no shared passwords.

## permission
Third, no one asks for permission. [#creep] Permission creep and forgotten access mean the attacker inherits everything. [#least] Consider least privilege, role-based permissions and periodic access reviews.

## good {hold=1.2}
What good looks like. [#design] Blast radius is a design choice, not a consequence. [#cost] Segmentation, tiered admin and least privilege cost engineering time. [#order] A breach that spreads company-wide costs orders of magnitude more. [#hours] With the controls, spread stops at one department. Hours, not days or weeks. [#afford] The question is not, can we afford to segment? It is, can we afford not to?

## first {hold=1.2}
A suggested first step. [#ask] Ask the CIO or the CISO for four numbers. [#a] Segments with firewalled boundaries. [#b] High-privilege accounts kept apart from routine work. [#c] Data that is classified and restricted, and access reviews completed.

## outro {hold=2}
Blast radius is a design choice. [#keep] Isolate before you have to.
